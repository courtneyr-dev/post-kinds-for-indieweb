> **WordPress.org versioning note:** the public WordPress.org debut is **[1.0.0] dated 2026-07-20**, which bundles the full feature set from the pre-release GitHub builds (1.4.3 and earlier, listed below) plus the final pre-launch fixes. ## [Unreleased]

### Added

- Check-in archive as a map and a list. The Check-ins Feed block has an archive mode (`inherit`): inside a Query Loop that inherits the main query it prints the page's check-ins as a linked list and, for the ones whose coordinates the visitor may see, a Leaflet map. `templates/taxonomy-kind-checkin.html` uses it at 24 a page, so page 2 lists and maps check-ins 25 to 48. A theme's own `taxonomy-kind` or `taxonomy-kind-checkin` template still wins (#224).
  - Pins come from the server, behind `pkiw_get_visible_location_fields()`. A public check-in gets a numbered pin and the same number beside its list entry. An approximate one keeps its venue name and place and gets no pin. A private one prints its title and date, the same markup as a check-in with no location. No coordinates, street, postal code, venue URL or venue id of those posts reach the page.
  - Check-ins within about 11 metres share one pin, named "3 check-ins at this location" with their list numbers; Enter on it moves focus to the first of them in the list. Pins that overlap at the current zoom merge into a cluster button that zooms in. Every check-in stays in the list.
  - Keyboard: the zoom buttons come before the pins in tab order; Enter on a pin moves focus to its list entry; each list number becomes a button (`aria-controls` the map, named "Show Evening walk on map") that centers the map on its pin, so nothing needs a drag. Pins, list numbers and zoom buttons are 44 by 44 CSS pixels. Reduced motion turns off zoom and pan animation.
  - The map is a named region described by a count line ("6 check-ins · 4 mapped"). It stays `hidden` until the script draws it, the list is complete without JavaScript, and Leaflet loads only on a page that has a pin.
  - `pkiw_map_tile_url` and `pkiw_map_tile_attribution` filters set the tile provider for this map and the Check-in Dashboard. The default is the OpenStreetMap tile service, which receives each visitor's IP address and the page's origin; name it in your privacy policy or point the filter at another provider.
  - The Site Editor previews the archive with the server's markup through the block renderer; only that endpoint stands in the newest check-ins for the template's query. The editor canvas loads Leaflet, MarkerCluster, their CSS and the map script, and draws the map with its pins beside the numbered list each time the preview renders, by the same consent rule as the front end. Opening this template, or any `taxonomy-kind-<slug>` template, no longer marks it changed: core's Query Loop wrote the site's posts per page and `excludeCurrent` into the inheriting loop on load, which turned on Save with no edit and let a save store a database copy over the shipped template. `pkiw_checkin_map_requires_consent` (default false) marks the map `data-pkiw-consent="required"`, and the map then loads no tiles until a `pkiw:map-consent` event on `document`, which can come before the page finishes loading, or `window.pkiwMapConsent = true`; the list stays complete. The two-column layout waits for a drawn map, so a hidden one no longer leaves the list in half the width. Enter and Space on a cluster zoom in, or spread it at the maximum zoom, and move focus to the pin of its first check-in in the list, or to the smaller cluster that still holds that pin; pins and clusters take focus in list order.
- A title generated from location data follows the location's privacy. The Foursquare sync, the importer and both OwnTracks paths record `_pkiw_title_source` = `location` when they write a title such as "Checked in at Venue". When the venue name is hidden, WordPress prints "Check-in, September 12, 2026" instead: in `the_title` (the `h1`, the hidden `p-name`, Stream cards, feeds, REST `title.rendered`, post navigation and link text) and in the document title. The stored title doesn't change, wp-admin lists it as stored, and retitling the post by hand clears the marker. A title an author wrote is never replaced. Posts imported before the marker existed are recognized when a private post's title is exactly its venue name or "Checked in at" plus that name. `pkiw_get_safe_title( $post_id )` returns the same value for themes, and `Meta_Fields::get_public_location_fields()` gives the visibility result without the editor override. Yoast SEO builds its title tag, Open Graph and X titles, schema, REST `yoast_head` fields and oEmbed title from the stored title, so those are corrected too (#224). A slug already stored from a hidden venue title becomes the date slug (see Fixed, #385, #386).
- Comic Card block (`post-kinds-indieweb/comic-card`) for a comic you read: title, creators, series, volume, issue number, publisher, cover with stored alt text, link, reading status, rating, start and end dates, and a note. The card is an `h-cite` with `u-read-of`, so the post's `h-entry` carries `read-of`, and a post that opens with the card gets the `comics` kind. A `comics` post with no card (a strip you drew) renders as before and carries no `read-of`. Only stored fields render. A comic still being read shows "Started" and never an end date, and stored dates print as the calendar day they hold whatever the site timezone. Stored text that isn't a real calendar day (`2026-02-30`, `tomorrow`) prints no date instead of a guessed one, and a rating above 5 reads as 5. Fields mirror into `_pkiw_comic_*` meta on save, exposed in REST, and the `post-kinds/kind-meta` bindings resolve `title`, `author`, `rating`, `url`, `cover_image` and `publisher` from them on comics posts (#228).
- Kind archive templates ship through the block template list: `taxonomy-kind` (a shelf of linked items for any kind) and `taxonomy-kind-eat` / `taxonomy-kind-drink` (a menu). Each has one `h1` (Query Title), the term description, a Query Loop that inherits the main query, centered Query Pagination with arrows, and a no-results message. A theme's own `taxonomy-kind` or `taxonomy-kind-{kind}` template, or a Site Editor customization, still wins (#233).
- Core block styles for Post Template: Shelf, face-out (`is-style-pkiw-shelf`), Shelf, spine-out (`is-style-pkiw-shelf-spine`) and Menu (`is-style-pkiw-menu`), plus Kind shelf and Kind menu Query Loop variations in the inserter. `styles/kind-layouts.css` draws shelf boards with pseudo-elements, so empty shelf space adds no DOM, and covers focus-visible, reduced motion, forced colors and a single column at 320 CSS px. Paint comes from new `--pkiw-shelf-*` and `--pkiw-menu-*` tokens (#233).
- Kind menu entry block (`post-kinds-indieweb/menu-entry`), used inside a Post Template: item name, a decorative leader hidden from assistive technology, "Rated N of 5" as text, venue name gated by `pkiw_get_visible_location_fields()`, date and notes, with the same `p-ate`/`p-drank h-food` microformats the cards emit. Section headings come from the cuisine or drink type at render time; posts without one are listed under "Other" (#230, #233).
- `pkiw_group_by` query var and `pkiw_archive_group_fields` filter: a kind archive rendered by a template that uses the menu entry is ordered by group (empty last), then date, then ID, so pagination stays native and pages are stable. A Query Loop can opt in with `query.pkiwGroupBy` (#233).
- `wp postkind card-meta backfill [--batch=<size>]` (#233).
- Recipe facts read when a page renders: `PKIW\recipe_facts()` returns a recipe post's picture, total time, yield and courses, `PKIW\recipe_time_label()` formats the time, and `PKIW\recipe_archive_courses()` lists the courses in use with their archive links. The Stream card for a recipe post prints its course and total time, and uses the recipe's picture when the post has no featured image (#229).
- Course filter and A-Z order on the recipe archive, as ordinary WordPress queries: `/kind/recipe/?pkiw_recipe_course=soup` and `/kind/recipe/?orderby=title&order=asc`. Both stay in the URL, so pagination keeps them. With WP Recipe Maker a course is a `wprm_course` term, resolved through each recipe's parent post. With no recipe plugin, courses are the post's categories; the `pkiw_recipe_course_taxonomy` filter picks another taxonomy (#229).
- `pkiw_recipe_plugin_active` filter over the WP Recipe Maker detection (#229).
- Helpers a theme's kind archives read instead of block attributes or raw meta: `PKIW\kind_facts()` returns a kind's facts from its registered reader (`Kind_Facts::register()`; `recipe_facts()` is the first), with nothing for a post the visitor can't read and location facts cut to the post's public tier; `PKIW\kind_picture()` returns one picture, the featured image before the card's cover, with a remote cover only when no local copy exists and a `suppress_featured` flag for a template featured image that would repeat it; `PKIW\normalize_host()` and `PKIW\url_host()` give one form for a host (lowercase, no `www.`, port or trailing dot, punycode as Unicode unless ICU's Spoofchecker flags the name, user info read to the last `@`), which the plugin's four inline `www.` strippers now use, and `_pkiw_cite_host` follows `_pkiw_cite_url` on every write. Card defaults now fill a key with no stored row even when the key registers a default, and eight card editors no longer send 28 unregistered meta keys that REST dropped (#234, #235, #238, #239, #253, #254, #255, #258, #259).
- `PKIW\kind_picture()` finds a cover's media library image in `_pkiw_cover_attachments`, a map of cover URL to attachment ID kept in step with the cover meta, instead of searching every attachment's file path once per post: 24 posts on a site with 2,000 attachments went from 24 searches (37 ms) to none. A post saved before the map existed searches once a request until it's saved again or the card backfill runs. `_pkiw_cite_host` names the cite URL `get_post_meta()` returns after any write, including a delete of one of two rows (#238, #239).

- Recipe courses block (`post-kinds-indieweb/recipe-courses`): a labelled `nav` of links to the recipe archive, "All", each course in use and "A–Z index", with `aria-current="page"` on the one being shown. It's server-rendered, so the Site Editor prints the same links as the front end. A theme places it in its recipe archive template (#229).
- The Site Editor previews a `taxonomy-kind-<slug>` template with that kind's posts. Core previews an inherited Query Loop with the site's latest posts for every taxonomy except categories, tags and post formats. `pkiw_kind_archive_preview_per_page` tells the preview how many posts a kind's archive shows per page. With no filter value and no menu entry "Lines per page", the preview shows the site's posts per page from the editor settings, since the Query Loop no longer writes that number into the template (#224, #229, #233).
- The Site Editor previews the eat and drink menus as the front end serves them: the lines come in menu order and a section is headed once. `orderby=pkiw_group` on the REST posts routes returns one menu kind by group, then date, then ID, and a menu line rendered on its own works out whether it starts a section from that order and the preview's page size (#230).

- Recent Specials block (`post-kinds-indieweb/menu-specials`) for the top of the eat and drink menus: the newest posts of the kind (two by default, one to six), each with its linked name, note, venue under the location privacy rule, date, "Rated N of 5" and an optional photo. It prints on the first page only and carries no microformats root, so the menu line stays the post's entry. The plugin's `taxonomy-kind-eat` and `taxonomy-kind-drink` templates place it above the menu (#230).
- Menu settings on the Kind menu entry block: lines per page for the kind archive (0 keeps the site's Reading setting), section order (A to Z or Z to A), where posts with no cuisine or drink type go (after or before the other sections) and the heading they get ("Other" when left empty). The archive's main query, the Site Editor preview and the REST posts route (`orderby=pkiw_group`, `pkiw_group_desc`, `pkiw_group_empty_first`, `pkiw_group_desc_empty_first`) all read them (#230).
- A Micropub `read-of` sent with `pkiw-kind: comics` builds a Comic Card instead of a Read Card, so the card matches the post's `comics` kind and its fields mirror into `_pkiw_comic_*` meta. The card takes `name`, every `author`, `read-status`, `rating`, `content` and the new vendor properties `mp-series`, `mp-volume`, `mp-issue-number`, `mp-publisher`, `mp-started-at` and `mp-finished-at`. The cover is `mp-cover-image` (alt `mp-cover-image-alt`), else the first `photo` with a URL, read as a URL or a JSON photo object; when Micropub has sideloaded that photo the card uses the local copy, and neither the remote URL nor the copy repeats below the card. Without the hint, or with `pkiw-kind: read`, a `read-of` still builds a Read Card, and a hint for any other kind sets the kind term but keeps the inferred card (#295).
- A post with a slide deck or a talk recording gets the `presentation` kind when it's saved. A Speaker Deck, SlideShare, Google Slides, Notist or Canva embed, a `[slideshare id=...]` shortcode, a WordPress.tv recording, or an authored `_pkiw_presentation_*` field (slides URL, event name, event URL, or a calendar source with an event ID) classifies it. A YouTube, VideoPress, Vimeo or Dailymotion embed alone doesn't, a link to a deck doesn't, and a post with a listen card or the `listen` kind is never claimed without a deck, a talk recording or authored fields. Existing podcast appearances aren't moved into Listen. Another kind card stays first, and a kind a person picked is never changed. `wp postkind presentation backfill [--dry-run]` prints each candidate with its kind, its `_pkiw_kind_auto_assigned` marker and its signals, and sets only the kind term, never updating the post, on posts with no kind, the default `note`, or a kind matching the marker (#210).
- Grouped kind archives run through one engine, `PKIW\Grouped_Archive`. A kind registers a group source: a meta key, or the first non-empty of several; a case computed from which meta a post has, the earlier case winning; a taxonomy term, first by name, with an optional term filed last and a one-term `?tag=` filter honored; or the post date's week, month or year in the site timezone. A block registers as an entry block, and an entry in the Post Template of the Query Loop that inherits the archive groups it. Headings print the value as stored, through a plugin label map, or as a date (`dateFormat`; weeks as a range such as "September 28 – October 4, 2026"), and an entry's `groupLabels` and `emptyLabel` replace them. A group that runs onto the next page repeats its plain heading there. `pkiw_archive_group_source` picks another registered source for a request or turns grouping off. The eat and drink menus print the same order and markup as before, with two changes: a menu entry outside the inheriting loop no longer sets the archive's page size or grouping, and in the Site Editor a post with two kinds previews as the kind of the template it sits in (#232, #234, #237, #241, #252, #253, #254, #255, #258, #259, #263, #265).
- Archive sections block (`post-kinds-indieweb/archive-sections`), the entry block a kind archive's Post Template holds to group its posts by the kind's registered source. It prints nothing itself. Each section is a `section.pkiw-group` with `data-pkiw-group` naming its group and a heading with an id, `pkiw-group-<slug>`, unique on the page, over a `ul.pkiw-group__items`. Its settings are lines per page for the archive's main query (`linesPerPage`), heading level, the heading for posts with no group (`emptyLabel`) and one per group (`groupLabels`); the labels stay editable in a `contentOnly` pattern. In the Site Editor a post that opens a section shows that section's heading. The Shelf and Shelf, spine-out styles reach the items of a sectioned Post Template, and a sectioned Post Template stacks its sections (#232, #234).
- Play kind archive. `templates/taxonomy-kind-play.html` serves /kind/play/ when the theme has no play or kind template: the archive title, the term description, Staff Picks, then the page's plays at 12 a page in sections, video games (a RAWG or Steam ID), then board games (a BoardGameGeek ID), then plays with neither, newest first within each, each as a level 3 Stream card. `PKIW\play_group()` and `PKIW\play_group_of_attrs()` name the group a post or a card files under, by the same rule as the stored IDs. `PKIW\kind_facts()` reads a play's status, hours, platform, review, links and provider IDs from post meta (`PKIW\play_facts()`), with hours as "3.5 hours played" and the game link as "View on BGG", "View on RAWG", "View on Steam" or the host (#232).
- Staff Picks block (`post-kinds-indieweb/staff-picks`): up to three top-rated board game plays (`count`, one to six), one per BoardGameGeek ID, on page 1 of the archive only. A pick is a published play with no password, in a viewable post type, with a BGG ID, no RAWG or Steam ID and a rating above 0, ordered by rating (a stored 8 counts as 5), then date, then ID. Each prints its box image with `alt=""` (the first with `loading="eager"` and `fetchpriority="high"`), its title as a link one heading level below the block heading, and "Rated N of 5", with no other facts and no microformats. The heading defaults to "Staff Picks" at level 2. On a later page, or with no play that qualifies, the block prints nothing, heading included (#232).
- Read kind archive. `templates/taxonomy-kind-read.html` serves /kind/read/ when the theme has no read or kind template: shelves by status, Currently Reading, To Read, Finished, then Abandoned, newest first within each, at 12 a page, with a shelf's heading repeated after a page break. The Read order block (`post-kinds-indieweb/read-order`) is a `nav` named "Read order" with All and A–Z by author links and `aria-current` on the view shown. `?pkiw_read_order=author` lists reads by author, then book title, blank authors last, with no shelves, and pagination keeps it. A password-protected read sorts by its post title with the reads that have no author, so its place doesn't give away the author it hides. `PKIW\read_status_labels()` is the one status label map for the read card, the `read_status` binding and the shelves (#234).
- A board game play card prints a tabletop, the same markup on every theme and in feeds. A card that files as a board game is marked `pk-card--tabletop` and `data-pkiw-play-group="board"` and holds the title, the box (`figure.pk-box`: the featured image, else the card's cover, with the stored alt or "Box art for %s"), the facts (`dl.pk-facts`: Platform, Status, Played as a date only, and Hours), the links (`div.pk-links`: the game URL labelled by host, Official Site and Buy, each saying it opens in a new tab) and a score pad (`section.pk-scorepad`): "Rated N of 5" as text beside `aria-hidden` stars, then, with a review, a Review heading and the review. The Review heading sits one level below the card title: an `h3` under the card's `h2`, or an `h2` when the card prints no title (an untitled card, or a card on its own post's page whose title matches the post title, where the title stays as hidden `p-name`). The Stream moves it by the same offset as the title, capped at `h6`, so the play archive's level 3 cards print an `h4` Review. In the editor an unselected board card previews through the server render (#232, #372, #382).
- A Micropub play whose `play-of` is a boardgamegeek.com `/boardgame/` or `/boardgameexpansion/` page sets the play card's BGG ID, and so does pasting one into the card's URL field. VideoGameGeek, BGG video game and RPG pages fill the game URL and title and set no BGG ID (#372).
- Review archive. `templates/taxonomy-kind-review.html` serves /kind/review/ when the theme has no review or kind template: the archive title, the term description, Four Stars, then the page's reviews at 9 a page in sections by category, the site's default category last. The Review entry block (`post-kinds-indieweb/review-entry`) prints each review as its title link, the item name as plain text, a decorative cover, and a hidden publish date and author. A password-protected review files under Other whatever its category. A theme's own review or `taxonomy-kind` template still wins (#252).
- Four Stars block (`post-kinds-indieweb/four-stars`): up to six reviews rated four on their own scale (4 of 5, 8 of 10), newest first. Set the heading ("Four Stars" by default), its level (2 to 4) and the count (1 to 6). It prints on page 1 of the review archive only, skips password-protected reviews, and prints nothing, heading included, when no review qualifies (#252).
- A review's rating, best rating, item name and item link fill from the post's first Star Rating block when the post is saved and when the card meta backfill runs. Rating and best fill as a pair only when the stored rating is unset, empty or 0. Item name and item link fill only when their stored value is empty. Editing the Star Rating block after the first fill doesn't change the stored rating, so the review archive and Four Stars keep showing the first value; the stored value is what they read. `PKIW\kind_facts()` returns a review's rating (stored value first, else the block's), best, item name and URL, "Rated N of 5" label, first pullquote and category (#252).
- Reply and like cards copy their citation into post meta when the post is saved: the card's URL, title, author, description and image go to `_pkiw_cite_url`, `_pkiw_cite_name`, `_pkiw_cite_author`, `_pkiw_cite_summary` and `_pkiw_cite_photo`. A title that is the URL isn't copied. `cite_url` and `cite_photo` are saved with `esc_url_raw()`, so `%E2%80%99` and `%20` survive, and a URL it empties (`javascript:`) is skipped rather than blanking a stored one. The bookmark card has no such map yet (#253, #254).
- Reply and like archives group by the cited site. `_pkiw_cite_host` holds the host of the first non-empty `cite_url`, `in_reply_to`, `like_of` or `bookmark_of` row (the `pkiw_cite_host_keys` filter changes the list) and is deleted when none is left. A host is lowercase, without `www.`, port or trailing dot. A post with no cited host, or a password-protected one, files in the empty group, so a protected reply or like doesn't open a second heading for the host it cites. Grouped archives take a flag for that (`protected_in_empty` on `Meta_Source` and `Term_Source`), and `Grouped_Archive::group_label_of_post()` returns the heading text for a post (#253, #254, #258).
- `PKIW\kind_facts()` reads replies and likes. A reply returns `url`, `host`, `cited_title`, `author`, `summary`, `picture` and `name`; a like returns the same without `name`. A bookmark returns `url`, `host`, `title`, `cited_title`, `author`, `note`, `rel`, `date`, `picture` and `drawer`, taking card attributes from the post's first bookmark card and falling back to cite meta for Quick Post and imports. Each returns nothing for a password-protected post or a private one the visitor can't read, and none returns a location (#253, #254, #258).
- Bookmark archive. Bookmarks file under a drawer named for the post's first tag, A to Z; untagged and password-protected bookmarks file in the empty drawer, headed "Other" unless the archive marker sets another label. `/kind/bookmark/?tag=alpha` shows that tag's drawer (see Fixed). The plugin ships archive templates for review but not for reply, like or bookmark; a theme places the sections for those kinds (#258).
- Stream cards cite what a reply, like or bookmark points at. The card adds a hidden `u-in-reply-to`, `u-like-of` or `u-bookmark-of` citation built from the post's cite URL, cited title and author, and keeps the full target URL, query string included. A review always takes the generic Stream card. The `pkiw_stream_card_after_date` action prints after the date line (#253, #254, #258).
- Singular pages carry the right microformats for three more kinds. A review wraps its body in `e-content p-description` inside the `h-review` and prints hidden `p-rating`, `p-best` and `p-item h-product` values read through `kind_facts()`, none of them for a password-protected review. A reply puts the reply card first and the rest of the body in one `e-content` div, so IndieBlocks leaves the card outside the content; replies that already have `e-content` and `?atproto` requests are untouched. A bookmark kept only in meta (Quick Post, an import) prints a hidden `u-bookmark-of`, and prints nothing when the URL is the post's own permalink, with or without a trailing slash. A cited author inside an `h-cite` no longer stops the entry from printing its own hidden author, which also fixes it for like, bookmark and repost cards (#252, #253, #258).

- Month archives for six more kinds. `taxonomy-kind-chicken`, `-photo`, `-favorite`, `-acquisition`, `-repost` and `-article` serve /kind/<slug>/ when the theme has neither that template nor `taxonomy-kind`. One engine source, `Date_Source( 'post_month', 'month' )`, files each post under the month of its local `post_date`, so a post at 2026-08-31 23:30 in New York sits under August. Chicken lists 24 a page; photo, favorite, acquisition and repost list 12; article uses the Reading setting's posts per page. Grouped archives can render their list as an `ol` (`'list' => 'ol'` on `register_entry_block()`), and `Grouped_Archive::current_page_ids()` gives a kind's entry block the IDs on the page, or the previewed page in the Site Editor.
- Archive sections block `dateFormat` setting. A month-grouped kind prints "Date format" in the inspector in place of the section-order, empty-group and empty-label settings it ignores. An empty value keeps the month name and year ("August 2026").
- 'Contents' Post Template style (`is-style-pkiw-contents`), the layout the article archive uses.
- Chicken archive. `PKIW\Chicken_Archive` registers the chicken facts reader (name, kind label, date, URL, picture; nothing for a protected post or a private one seen by a logged-out visitor) and the Chicken entry block (`post-kinds-indieweb/chicken-entry`): one `li.h-entry` per post with a `time.dt-published` and a linked title. Two posts with the same title on one day, and untitled posts, get an accessible name that carries the date and, for the same day, the time. An untitled private or protected post prints no "Private:" or "Protected:" name (#250).
- Photo archive and photo singles. `Photo_Archive` registers the photo facts reader and the neutral photo template (12 a page, month headings, one frame per photo). The photo projector, `Photo_Projector`, turns the first `core/gallery` with two or more images on a photo single into a carousel region: Previous and Next buttons, an "N of M" counter and the caption in one polite live region, a rail of thumbnails, arrow keys only while focus is inside the region, no timers. A single image gets one mount, and a post with only loose images keeps core's markup. A slide's caption is the figcaption already on the image, else the attachment excerpt, never both. The `pkiw_photo_projector_labelledby` filter swaps the region's `aria-label` for `aria-labelledby` (#241).
- `PKIW\lead_image()` and `PKIW\featured_in_content()` pick a photo's lead image from the post content first (a block image, then an attached image, then the featured image). An image with no ID counts only when its URL is under the uploads folder and resolves to an attachment, including `-WxH` and `-scaled` names. Nothing fetches a remote image, and a protected post gets no lead (#241).
- Photo Stream cards print one card link and no meta line, kind badge or thumbnail strip. A titled photo's image has an empty `alt`; an untitled photo's image keeps its stored alt. A stored caption keeps its links, as article hero captions do (#241).
- Favorite archive and facts reader. `Favorite_Archive` registers the favorite reader (`has_card`, `cited_title`, `url`, `host`, `author`, `summary`, `rel`, `favorited`, `picture`, `name`, `name_is_title`; nothing for a protected or unreadable post). It reads the card, then `_pkiw_favorite_*` meta, then the cite meta, and never parses a link out of the post body. The Stream card for a favorite adds a hidden `u-favorite-of` citation when the post has a URL. A favorite single gets a hidden `u-favorite-of` from stored meta when its card doesn't carry the citation (#259).
- Acquisition archive and facts reader. `Acquisition_Archive` registers the acquisition reader and ships `taxonomy-kind-acquisition` (12 a page, month sections). The acquisition card has an "Inherited" type, an editable acquired date, and `u-acquisition-of` as its one microformat property (the `u-acquired` class is gone). An acquisition post's permalink gets the `h-entry` root with `u-acquisition-of` (#239).

Scoped that rule to `.editor-styles-wrapper` (editor canvas only), so front-end cards keep their intended spacing and shadow.

## [1.4.2] - 2026-07-07

### Changed

It is no longer applied to article/review/recipe kinds or plain admin-written posts, so long-form content stays out of the stream. The bare `note` kind alone no longer qualifies (it is auto-assigned to plain posts); a note needs a Status/Aside format or a Micropub origin to count. ## [1.2.0] - 2026-07-04

### Added

- **Book fields are now bindable kind-meta keys.** `isbn`, `publisher`, `pages`, `publish_date`, and `asin` join the Block Bindings source (with `pk_*` aliases), backed by matching `_postkind_read_*` post meta. Any block attribute can bind to book metadata the same way it already could to title, author, and cover.
- **Book completion cascade** (`includes/class-book-completion.php`). Given a partial book (say, just an ISBN), fills the missing fields by querying Open Library, then Google Books, then Hardcover — first source with an answer wins, existing values are never overwritten. Runs on editor save, on Micropub-created read posts (opt-out via the `pkiw_micropub_book_completion` filter), and on demand from the Read Card's editor button via the `/pkiw/v1/book-complete` REST route.
- **Kindle embed bridge.** A computed `kindle_embed_url` binding key builds a Kindle reader embed URL from the post's book meta — from the ASIN when present, otherwise derived from the ISBN (ISBN-13 → ISBN-10). Read posts with the opt-in marker render the embed as a lazy-loaded iframe on the front end at render time; nothing is stored in post content.
- **Read + Kindle preview block pattern and inspector toggle.** A registered pattern pairs the Read Card with the Kindle preview, and the Read Card's inspector gets a toggle that adds or removes the embed marker.
- **Card meta sync** (`includes/class-card-meta-sync.php`). On save, mirrors the post's first card block attributes into `_postkind_` meta (map-driven; read-card first), so Block Bindings always have a server-side source of truth that matches what the card shows.
- **Field-matrix test coverage across all 22 blocks (~290 attributes).** A generated fixture (`tests/phpunit/fixtures/field-matrix.json`) with a drift guard is the single source of truth for block attributes; matrix-driven suites cover server render (every attribute must reach the markup), static serialize, editor save/reload round-trips, visual-regression baselines for every card block, and the Micropub wire format per kind (mapped attributes asserted, declared gaps enforced).
- **Editor saves now set the kind term from the post's first block.** When a post's first block is one of the kind card blocks (eat, drink, listen, watch, read, play, checkin, RSVP, like, favorite, jam, wish, mood, acquisition), saving assigns the matching `kind` taxonomy term automatically — no separate pick in the taxonomy panel needed. Manual choices always win: only the `note` default (never chosen by a person) or a kind this sync itself assigned earlier (tracked in `_pkiw_kind_auto_assigned` post meta, so a swapped first block re-syncs) is ever replaced. Companion to the Micropub-side kind assignment, which covers posts arriving via the Micropub bridge.
- **Micropub bridge coverage for the four response kinds.** Likes render the Like Card (falling back to the liked URL as the linked title); reposts, bookmarks, and replies emit paragraphs carrying `u-repost-of` / `u-bookmark-of` / `u-in-reply-to` microformats2 classes until dedicated card blocks exist. Endpoint-level e2e tests cover all four shapes plus the rsvp/reply precedence rule.
- `docs/micropub-field-gaps.md` documents, kind by kind, which block fields Micropub clients cannot set yet — the concrete list for sender-side (Outpost) follow-on work.

### Fixed

- **Eat Card's restaurant and Play Card's steamId never rendered.** Both attributes existed in the editor and saved fine, but `render.php` never read them, so the values silently vanished on the front end. Caught by the new render matrix.
- **Mood Card and Play Card wiped freshly-entered values on editor mount.** Their "sync post meta → block attributes" effects read `_postkind_mood_*` / `_postkind_play_*` meta keys that were never registered, so every mount saw an empty meta value and stomped the attribute back to blank. Both effects now only apply non-empty meta values. Caught by the new round-trip matrix.
- **Micropub play and RSVP posts dropped fields to attribute-name mismatches.** The bridge's `play_card()` wrote `playUrl`/`gameTitle` and `rsvp_card()` wrote `response`/`note`, but the block schemas define `gameUrl`/`title` and `rsvpStatus`/`rsvpNote` — the values were silently discarded on render. Caught by the wire-matrix completeness assertion.
- **"Phantom posts" for contentless likes, reposts, bookmarks, and replies.** Same failure class fixed for eat/drink/follow/weather in 1.1.0: `like-of`, `repost-of`, `bookmark-of`, and (content-free) `in-reply-to` posts died inside `wp_insert_post()` with `empty_content` while the Micropub endpoint answered 2xx with no Location — on installs without IndieBlocks, the four response shapes Outpost sends created nothing at all. The bridge now recognizes all four in `detect_kind()` and supplies markup before insert.
- **Like Card block registered server-side.** `like-card` existed in `src/blocks/` and registered in the editor, but was missing from the server registration list in `class-plugin.php`.
- **Card block renders no longer make live oEmbed HTTP requests.** `wp_oembed_get()` performs an uncached discovery fetch on every call, so jam/listen/watch card renders outside the post-content cache path (REST, widgets, `do_blocks()`) blocked page render on a remote request. The three call sites now share a cached-embed helper backed by WordPress's oEmbed cache, with link-tag discovery disabled so only registered providers are ever fetched.
- **ASIN detection no longer trusts spoofable hostnames.** The Kindle bridge's Amazon host guard matched Amazon-looking substrings anywhere in the hostname; it now anchors to real Amazon domains.
- **The book-complete REST route no longer reflects unknown parameters.** `rest_complete()` built the book from all request params, so unrecognized keys bypassed the registered-args sanitization and echoed back verbatim in the response. Input is now intersected against the canonical book keys.

### Changed

- **Like Card is now a dynamic block** (`render.php`, jam-card precedent), so attribute-only blocks written by the Micropub bridge render on the front end. Existing statically-saved like cards migrate via a block deprecation; no content changes needed.

The bridge now supplies the card-block markup on the `micropub_post_content` filter, before insert, so the post is never empty. Endpoint-level integration suite (`tests/e2e/micropub-kinds.spec.js`) runs against a real wp-env with micropub + indieauth active. (#56)

- **Follow and weather kinds recognized by the Micropub bridge.** `follow-of` renders a paragraph whose link carries `u-follow-of`; `weather` renders its reading in a `p-weather` span. Previously both were unrecognized and (being contentless) created nothing at all. (#56)

### Changed

### Changed

The AI enhancement layer calls `wp_ai_client_prompt()`, which only ships in WP 7.0+, and declaring 6.9 support alongside that call tripped Plugin Check's `wp_function_not_compatible_with_requires_wp` error. Rather than suppress the check, the support floor moves to 7.0: `Requires at least` (readme.txt + plugin header), the `POST_KINDS_INDIEWEB_MIN_WP` activation guard, the wp-env core pin, the CI test matrix, and the docs now all say 7.0. ### Fixed

- **Plugin Check compliance.** `includes/class-cli-commands.php` now uses a standalone `ABSPATH` guard (the combined ABSPATH + WP_CLI guard was behavior-identical, but the `missing_direct_file_access_protection` sniff only recognizes a standalone check), and the `uninstall.php` variables use the full `post_kinds_for_indieweb_` prefix so `WordPress.NamingConventions.PrefixAllGlobals` stops warning.
- **Photo gallery posts no longer render the same images twice.** The Micropub-to-block bridge's `photo_card()` now deduplicates the `$input['photo']` array before emitting `core/image` blocks. The upstream Micropub plugin (David Shanske's `wordpress-micropub`) enriches `$input['photo']` post-sideload with a 2× version of the original array — when an Outpost gallery uploads 3 images and posts them as `photo[]=url1&...`, the array arriving at `after_micropub` priority 30 has 6 entries (originals + canonical URLs, both resolving to the same local URL on a single-server install) while `mp-photo-alt[]` still has only 3. Without dedupe, a 3-photo gallery rendered 6 image blocks: the first 3 with matching alts, the last 3 with empty alts. Dedupe is by URL, first occurrence wins (which is also the occurrence with its aligned alt text). 3 new PHPUnit tests in `MicropubContentBuilderTest.php` cover the staging-reproduced symptom (6→3 dedupe), the alt-alignment ("first occurrence keeps alt"), and the single-image collapse (3 identical URLs collapse to 1 image, gallery wrapper drops away).

### Added

- **Photo / gallery handling in the Micropub-to-block content bridge.** Photo posts (Micropub `photo` property without one of the specific of-kinds like `eat-of`, `watch-of`) now emit a `core/image` block (single photo) or a `core/gallery` wrapper (multi-photo) inside the same `h-entry` envelope as the other card kinds. Each `core/image` block resolves the photo URL back to its attached media ID via `attachment_url_to_postid()` so the block carries the canonical reference + `class="wp-image-{id}"` for srcset rendering. Alt text comes from the parallel `mp-photo-alt[]` array. Single-photo posts skip the gallery wrapper for a cleaner shape; multi-photo posts get `core/gallery` with `linkTo: none`. The user's typed body text still appears as `e-content` alongside the gallery.
  - 13 new PHPUnit tests covering: photo kind detection (alone + precedence vs other of-kinds), single vs multi-photo card output, attachment ID resolution, missing alt array, missing photo property, `flatten_string_array` helper across scalar/array/missing/non-string entries, and end-to-end `apply()` for both single and multi-photo posts.
  - Bridges any Micropub client (Outpost, Quill, Indigenous, etc.) to native Gutenberg gallery blocks without requiring the client to know about block markup.

### Fixed

- **Single posts no longer render the venue archive template.** `add_plugin_templates` was injecting `taxonomy-venue` into every `get_block_templates()` query result, including the hierarchy lookups that WordPress runs while resolving the single-post template (`slug__in => ['single-post', 'single', 'singular', 'index']`). When `singular` reached the resolver with no theme template registered for that slug, the plugin's `taxonomy-venue` template won the match and rendered for ordinary single posts — producing an empty `<main>` plus an unrelated query pagination block instead of the post body. The filter now respects `slug__in` and only injects when the requested slugs actually include `taxonomy-venue`. Adds four regression tests in `PluginTest.php`.

### Added

- **Micropub-to-block content bridge** (`includes/class-micropub-content-builder.php`). Hooks `after_micropub` priority 30 and rewrites Micropub-created `post_content` from plain text to the registered card blocks (Checkin Card, Eat Card, Drink Card, Listen Card, Watch Card, Read Card, Play Card, RSVP Card, Mood Card) when the incoming h-entry shape matches a recognized post kind. Bridges any Micropub client (Outpost, Quill, Indigenous, etc.) to this plugin's block-editor cards without requiring the client to know about Gutenberg block markup.
  - **Idempotent.** Sets a `_pkiw_block_content_generated` post meta marker on first generation; subsequent Micropub updates leave (potentially user-edited) content alone.
  - **h-entry envelope.** Wraps each card in a `wp:group` with `class="h-entry"` and an inner `e-content` group for the user's typed body text, so microformats2 readers see one h-entry root and the body in `e-content`.

  - **Outpost-friendly.** Recognizes Outpost's `mp-place-name` extension property as the venue name attribute. Outpost-made checkin/eat/drink/listen posts now render with proper card UI on the front-end.
